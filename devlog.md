## 2026-10-17 — Phase 1 step 1: skeleton and security shell

**Built:** `go.mod` (module `github.com/Labyricorn/Labbonet`); `cmd/labbonet` (flags, startup, graceful shutdown, best-effort `--open`); `internal/server` (loopback listener, Host allowlist, Origin/`Sec-Fetch-Site`/`X-Labbonet` checks, session cookie middleware, security headers incl. the Phase 1 CSP, one-time launch-code session flow, data-dir lock file) and its `servertest` helper; `internal/api/health.go`; `frontend/` placeholder (`index.html`, `app.css`, `app.js`, embedded via `frontend/embed.go`).

**Tests:** unit tests for S1–S7 and A-B2/A-B3 in `internal/server` (`go test ./...` passes; `gofmt -l .` and `go vet ./...` clean). Manual smoke test: ran the real binary, redeemed the launch code via curl and via the browser pane, confirmed `/api/health` and the static page serve correctly, confirmed a second instance against the same data directory is refused by the lock file, confirmed the original listener is undisturbed when the configured port is already in use.

**Discoveries:**
- `go.mod`'s `go` directive is pinned to the exact installed toolchain version (`go 1.26.2`) by `go mod init`; left as-is rather than hand-trimming to `go 1.26`, since Go treats a full version as a toolchain requirement, not a behavior change.
- The frontend embed (`//go:embed`) must live in a Go file *inside* `frontend/` (package `frontend`), not in `internal/server`, because embed patterns are resolved relative to the source file's own directory. `internal/server` imports the `frontend` package's `embed.FS` instead of embedding the files itself.
- `GET /launch` returns a 303 redirect to `/`. In tests the server has no frontend configured (`Config.Frontend` is nil), so following that redirect 404s — not a routing bug. `servertest.Start` now uses a client with `CheckRedirect: http.ErrUseLastResponse` and asserts 303 directly, rather than following the redirect.
- Confirmed Go 1.22+ `ServeMux` method-prefixed patterns (`"GET /launch"`) work as expected with the middleware chain wrapping the mux, since middleware wraps the mux pointer, not a snapshot — routes registered after `server.New` (e.g. `/api/health`, added by `main` after construction) still resolve correctly.

**Deviations from the plan file:** none. Rules S1–S7 and A-B2/A-B3 behave exactly as specified in `SECURITY-MODEL.md` and `PHASE1-ACCEPTANCE.md`.

**Not done here (by design, scoped to step 1):** storage, endpoint/credential/egress, provider adapter, generation pipeline, real frontend views, and the live/manual sign-off tests all remain for steps 2–7 of `docs/PHASE1-PLAN.md`.

## 2026-10-17 — Phase 1 step 2: storage

**Built:** `modernc.org/sqlite` added at v1.60.1 (BSD-3-Clause, confirmed from the vendored module's `LICENSE` file; `ARCHITECTURE.md` section 8 flipped from "Planned" to "Added"). `migrations/` (new top-level package, `embed.go` + `0001_init.sql`: `endpoints`, `endpoint_credentials`, `models`, `conversations`, `messages`, `generations`, plus supporting indexes). `internal/store`: `store.go` (`Open` sets WAL, `foreign_keys=ON`, `busy_timeout=5000`, a single max-open-connection since SQLite serializes writes anyway); `migrate.go` (parses `NNNN_*.sql` filenames for version order, applies each migration in its own transaction, refuses and leaves the file untouched if `PRAGMA user_version` is already past the newest embedded migration); `time.go` (shared RFC3339Nano timestamp codec); one typed query file per table (`endpoints.go`, `credentials.go`, `models.go`, `conversations.go`, `messages.go`, `generations.go`); `backup.go` (`VACUUM INTO` a timestamped file under `backups/`, then opens that copy on its own connection to `DELETE FROM endpoint_credentials` and `VACUUM` it, per DR-016); `storetest/` (mirrors `servertest`: `New`/`NewWithDir` give a fresh migrated database in a temp dir). `internal/api/backup.go` (`BackupHandler`) wired into `cmd/labbonet/main.go` as `POST /api/backup`, opening the store at `<data-dir>/labbonet.db` alongside the existing lock and session manager.

**Tests:** `internal/store/migrate_test.go` (A-B5 fresh start + restart keeps data and `user_version`; A-B6 migrate from an empty database, reopening an already-migrated database is a no-op; A-B7 refuses `user_version=999`, confirmed byte-identical file before/after); `internal/store/backup_test.go` (A-B8: restore by copying the backup file over the live database gives an identical conversation and message set, with `HasCredential` false in the restored copy); one query test file per table covering create/get/list/update/delete and the cascade deletes (`ON DELETE CASCADE` for credentials, models, messages, generations) plus A-E6 (same model ID on two endpoints stays two rows) and A-C8/A-C11 (reported vs. requested model, full provenance fields). `internal/api/backup_test.go` exercises `BackupHandler` directly against a `storetest` store. `gofmt -l .`, `go vet ./...`, `go test ./...`, `go build ./cmd/labbonet` and `CGO_ENABLED=0 go build ./...` all pass.

**Discoveries:**
- `modernc.org/sqlite`'s `database/sql` driver executes a multi-statement string passed to a single `Exec` call statement-by-statement (confirmed empirically: `0001_init.sql`'s six `CREATE TABLE` + four `CREATE INDEX` statements all apply from one `tx.Exec(rawFileContents)`), so `migrate.go` only strips comments/blank lines and splits on top-level `;` for clarity, with no need for a driver-specific workaround.
- `PRAGMA user_version = N` can be executed inside the same transaction as the schema statements it follows; committing both together is what makes "apply in one transaction" and "track by user_version" the same step, not two.
- Restoring a `VACUUM INTO` backup over the live file needs the original's `-wal`/`-shm` siblings removed first (the test does this), otherwise SQLite's WAL recovery on next open can reapply stale frames from the old file instead of reading the restored one directly.
- Chose `INTEGER PRIMARY KEY AUTOINCREMENT` IDs for every table except `models` (natural composite key `(endpoint_id, model_id)`, per "model identity is always the pair") and `endpoint_credentials` (one-to-one on `endpoint_id`). `ARCHITECTURE.md` section 5 lists key columns but not ID types; this is an implementation default in the same spirit as section 1, not a new entry there, since nothing outside this step depends on the choice yet.

**Deviations from the plan file:** none in scope. The "migration test from an empty database and from 0001" in `PHASE1-PLAN.md` step 2 is, as of this step, the same test twice over (there is only one migration, so "from 0001" and "from empty" are the same starting point); `TestMigrate_FromEmptyDatabase` notes this and also re-opens an already-migrated database to prove re-migration is a no-op, which is the part of that requirement that will matter once a `0002_*.sql` exists.

**Not done here (by design, scoped to step 2):** endpoints/credentials CRUD API, egress client, provider adapter, generation pipeline, frontend, and the live/manual sign-off tests remain for steps 3–7.

## 2026-10-18 — Phase 1 step 3: endpoints, credentials and egress

**Built:** `internal/secrets` (`Protector` interface; `dpapi_windows.go` using `golang.org/x/sys/windows` `CryptProtectData`/`CryptUnprotectData` directly — no DPAPI wrapper needed, the bindings and `DataBlob` type are already in `x/sys/windows` — current-user scope, `CRYPTPROTECT_UI_FORBIDDEN`; `unsupported_other.go` returns `ErrUnsupported` on every other platform, no plaintext fallback). `internal/egress` (the only package allowed to make outbound HTTP requests): `classify.go` (`Classify`/`IsMetadata` on `net.IP`, built on the stdlib's own `IsPrivate`/`IsLoopback`/`IsLinkLocalUnicast`, which already cover RFC 1918 and IPv6 ULA); `paths.go` (fixed allowlist from `PROVIDER-SPEC.md` 1.5); `client.go` (`Client.Do`/`DoLimited`, `Target{BaseURL, PrivacyClass, Credential}`, a `net.Dialer.Control` hook as the dial guard, `CheckRedirect` that always refuses); `isolation_test.go` (greps `cmd/` and `internal/` for `http.Get(`, `http.Client{`, `net.Dial(` outside `internal/egress` and the `servertest`/`storetest` test-helper packages). `internal/endpoints/registry.go` (`ValidateBaseURL`; `ClassifyAddress` resolves via `net.DefaultResolver.LookupIPAddr`, calls into `internal/egress`'s classifier, refuses metadata addresses, requires `acknowledgeExternal` for public ones). `internal/api/endpoints.go` (`Endpoints{Store, Protector}`: `List`, `Create`, `Patch`, `Delete`, `SetCredential`, `ClearCredential`; every endpoint registers with `provider_type: "openai"`, per `PROVIDER-SPEC.md` section 3 — detection is step 4's `/test`, not registration). `internal/store/endpoints.go`: added `UpdateEndpoint` (name/enabled/concurrency_limit only — the base URL and privacy class are fixed at registration). `internal/server`: `redact.go` (`RedactHeaders`, strips `Authorization`/`Cookie`/`Set-Cookie`) and `accesslog.go` (`AccessLog` middleware logging method/path/status/duration only, never headers or bodies), wired into `server.Config.Logger` (nil-safe) and `cmd/labbonet/main.go` (`dataDir/logs/access.log`). `go.mod`: `golang.org/x/sys` promoted from indirect to a direct require at the same v0.48.0 (BSD-3-Clause, confirmed from the vendored module's `LICENSE`); `ARCHITECTURE.md` section 8 flipped to "Added".

**Tests:** `gofmt -l .`, `go vet ./...`, `go test ./...`, `go build ./cmd/labbonet` and `CGO_ENABLED=0 go build ./...` all pass. S8 (redirect refused), S9 (dial-guard class mismatch, tested both as a pure table test on `checkDialAddress` and end-to-end against a real `httptest` server through the real dialer), S10 (metadata address refused, at both the registry layer and the dial guard), S11 (credential scoped to its own `Target`, checked with two capture servers), S12/S13 (`credential_set` only, secret absent from any JSON response) in `internal/egress` and `internal/api`. `TestOnlyEgressMakesOutboundRequests` (the step's "no code path outside `internal/egress` makes an outbound HTTP request" done-criterion) passes. Manual smoke test against the real binary: registered a `local` (`127.0.0.1:8080`) and a `lan` (`10.138.11.11:1234`) endpoint, confirmed a public address is refused with 409 until `acknowledge_external: true` and a metadata address (`169.254.169.254`) is refused with 400, set and cleared a credential, patched and deleted an endpoint, took a backup, and grepped the database, the backup file and `logs/access.log` for the credential value — not present anywhere.

**Discoveries:**
- `golang.org/x/sys/windows` already exports `CryptProtectData`, `CryptUnprotectData` and the `DataBlob` struct directly (`syscall_windows.go`/`types_windows.go`/`zsyscall_windows.go`); no extra DPAPI shim package was needed. The output blob's buffer is allocated by DPAPI itself and must be copied into a Go slice and then released with `windows.LocalFree`, or it leaks.
- `net.Dialer.Control`'s hook runs after the socket is created but *before* `connect()`, and receives the already-resolved numeric address. That makes it the right place for the dial guard: a refusal there means literally no packet is ever sent, it re-runs on every connection (so a later DNS answer in a different class is caught, not just the first), and — usefully for testing — it means `checkDialAddress` can be exercised against addresses like `169.254.169.254:80` or `8.8.8.8:443` with no real network dependency and no flakiness, since the connection attempt never gets far enough to need one.
- Go's stdlib `net.IP.IsPrivate()` (Go 1.17+) already covers RFC 1918 and IPv6 ULA (`fc00::/7`) directly, so `egress.Classify` needed no hand-rolled CIDR tables — only `IsMetadata` needed an explicit address list, since `169.254.169.254` would otherwise classify as `lan` via `IsLinkLocalUnicast`.
- Kept `internal/endpoints.ClassifyAddress` as a one-time *suggestion* at registration (it does its own `LookupIPAddr`, separate from the dial guard's own resolution at connect time) rather than trying to share a resolution with `internal/egress`'s dial guard — the dial guard is the actual enforcement point and re-checks on every real connection regardless, so registration-time classification only has to be good enough to pick a sensible default and to gate the external-acknowledgement requirement.

**Deviations from the plan file:** the plan lists a "Log redaction helper used by the server logger" as a step 3 file; Phase 1 had no request logging at all yet, so this step also added the minimal access logger itself (`internal/server/accesslog.go`, method/path/status/duration only) rather than only the redaction helper in isolation — `RedactHeaders` remains available for any future code that wants to show headers (e.g. diagnostics in step 5) but nothing currently calls it outside its own test, since the access logger was designed to never need it.

**Not done here (by design, scoped to step 3):** provider detection (`/test`, LM Studio vs. Strata vs. generic), model discovery, and actually calling `egress.Client` from a provider adapter all remain for step 4. The egress client's idle-chunk timeout for streaming responses is deferred to step 4/5, since step 3 has no streaming caller yet.

## 2026-10-18 — Phase 1 step 4: OpenAI adapter

**Built:** `internal/providers/provider.go` (the `Provider` interface, `Model`, `ChatRequest`/`Message`, the normalized `Event`/`EventKind`, `Result`, and the `Error`/`ErrorKind` taxonomy from `PROVIDER-SPEC.md` sections 1 and 1.3). `internal/providers/openai` (the one adapter every endpoint uses): `detect.go` (`/health` → `/api/v0/models` → `/v1/models`, in that order, recording the profile as `strata`/`lm-studio`/`openai-compatible`); `models.go` (one normalizer per profile's model-list shape — Strata's `status.value`/`meta.n_ctx`/`architecture.input_modalities`, LM Studio's `type`/`state`/`max_context_length`/`capabilities`, and a bare-IDs generic fallback); `sse.go` (`parseSSELine` for the "ignore blank lines and `:` comments, stop at `data: [DONE]`" framing rule, `normalizeChunk` turning one decoded chunk into zero or more events, with LM Studio's `stats` as a fallback source for timings when Strata's own `timings` object is absent); `chat.go` (`buildChatBody` applying the per-profile extras allowlist, `StreamChat` driving the SSE loop and `emit`ting events); `errors.go` (HTTP status + the observed `{"error":{"type","message"}}` shape → `ErrorKind`, plus `mapRequestError` for transport-level failures). `internal/providers/fakeprovider` (the shared scriptable OpenAI-compatible test server from `PHASE1-PLAN.md` section 2: fixed `/health`, `/v1/models`, `/api/v0/models`, `/v1/chat/completions` routes driven by a `Script`, with knobs for a mid-stream drop, a slow first byte, a one-path redirect, and `LastAuthHeader()` for credential-scoping tests). `internal/api/models.go` (`Models{Store, Protector, Egress}`: `Test`, `Refresh`, `List`), wired at `POST /api/endpoints/{id}/test`, `POST /api/endpoints/{id}/models/refresh`, `GET /api/endpoints/{id}/models`. `internal/store/endpoints.go`: added `SetDetectedService`.

**Tests:** `gofmt -l .`, `go vet ./...`, `go test ./...`, `go build ./cmd/labbonet` and `CGO_ENABLED=0 go build ./...` all pass. SSE parser table tests built from the `Strata_Protocol.md` section 5.3 example (keep-alive comments, the role/empty-content first chunk, `finish_reason: "length"` with a null `content` treated as a truncation rather than an error, LM Studio's `stats` fallback). Every error kind in `PROVIDER-SPEC.md` 1.3 that maps from an HTTP status has a table test producing it (`auth`, `model_not_found`, `no_model_loaded`, `busy`, `context_overflow`, `upstream_error`), plus `cancelled`/`timeout`/`unreachable` from `mapRequestError`. `TestDetect_Strata`/`_LMStudio`/`_Generic`/`_Unreachable` and `TestListModels_Strata`/`_LMStudio`/`_Generic` against `fakeprovider`, including an embeddings model from the LM Studio shape coming back `Chat: false`. `TestModels_Test_CredentialScopedToItsOwnEndpoint` (S11, at the API layer this time, with two fake servers and `LastAuthHeader()`). A-E2/A-E3-style live checks against the real hosts: with the backend running, registered both Strata (`127.0.0.1:8080`) and LM Studio (`10.138.11.11:1234`), ran `/test` against each (detected `strata` and `lm-studio` respectively, persisted to `detected_service`), and ran `/models/refresh` against each (Strata returned its one loaded model with `reasoning_field: "reasoning_content"` and `context_length: 65536`; LM Studio returned its full inventory with per-model `state`, `vision`/`tools` from `type`/`capabilities`). A one-off program (run from inside the module tree, since `internal/` packages cannot be imported from outside it, then deleted) exercised `StreamChat` against the live, already-loaded Strata model with `max_tokens: 5` — a tiny generation, not a probe, matching the AGENTS.md exception — and confirmed the full event sequence (`start`, `reasoning` deltas, `done` with `finish_reason: "length"`, `usage`, `timings`) end to end against the real server.

**Discoveries:**
- The live Strata instance's served model and context length had both changed since `Strata_Protocol.md` was written (`qwen3.8-flash-next-iq3_s`, `max_context: 65536`, vs. the document's `qwen3.8-flash-next-unsloth-ud-iq4_xs`/32768) — expected drift for a locally-managed model file, and exactly why the adapter records the server-reported model ID rather than trusting any document or the requested one.
- `internal/` import visibility is enforced by directory tree, not by module membership: a throwaway verification program has to live somewhere under the module root (even a temp subdirectory, deleted afterward) to import `internal/providers` or `internal/egress`; a file in the OS temp directory or the session scratchpad cannot, even though it is the same Go module.
- Normalizing LM Studio's model list needed no live probe of its chat/stream endpoint (still open per `PROVIDER-SPEC.md` section 7) — `type`, `state`, `max_context_length` and `capabilities` from `/api/v0/models` were enough to build the full capability profile per PROVIDER-SPEC.md section 2, confirmed against the real inventory (28 models, a mix of `llm`/`vlm`, all `not-loaded` at probe time, `tool_use` present on several).
- Keeping `buildChatBody`'s struct with no field at all for `strata_mcp` or `ttl` (rather than a field that is conditionally zeroed) makes "never sends" a property of the type itself, not of call-site discipline, which is also what `TestBuildChatBody_NeverSendsStrataMCPOrTTL` checks on the actual marshaled JSON rather than trusting the Go source alone.

**Deviations from the plan file:** none. Cancellation is tested at the unit level (`mapRequestError` on `context.Canceled`, `StreamChat` with an already-cancelled context) rather than by interrupting a real in-flight stream, since reproducing a genuine mid-flight cancel deterministically needs the fakeprovider's chunked-write timing more than this step's scope called for; `Strata_Protocol.md` section 10 already tracks live cancellation and cold-load timeout testing as open items for step 7.

**Not done here (by design, scoped to step 4):** conversations, the generation pipeline (persisting messages, concurrency slots, the `not-loaded` confirmation guard), and the `/api/conversations/{id}/generate` SSE route all remain for step 5. LM Studio's own streaming shape (whether `stats` actually appears, as opposed to the Strata `timings` object) is still untested live, per `PROVIDER-SPEC.md` section 7 — step 4 only probed `/health` and the two model-list endpoints, deliberately not sending a chat request to any `not-loaded` LM Studio model.
