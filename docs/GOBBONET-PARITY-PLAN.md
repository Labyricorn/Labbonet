# GobboNet application parity plan

**Status:** owner authorized implementation with “implement this plan” (2026-10-17); milestone 1 backend/UI implemented in the working tree, verification closeout still in progress. Attribution inventory audited 2026-10-18. See `IMPLEMENTATION-HANDOVER.md` for working-tree status.
**Requested:** 2026-10-17, "Add full functionality from Gabbonet to Labbonet."
**Reference:** GobboNet 1.7.6, commit `314bdc9cae204ae38fdc1002ac6a9fb1437c109f`.

Labbonet is not affiliated with GobboNet or its authors. This plan covers the pinned application's user-facing functionality, subject to Labbonet's accepted security and provider boundaries. It does not claim that the current application has parity.

## Scope and phase order

Propose completing GobboNet application parity before the original Phase 2 WebLLM work and Phase 5 multi-model expansion. Those Labbonet additions remain on the roadmap; they are not prerequisites for reproducing GobboNet. This is a proposed sequencing change to proposal section 20, not an amendment of accepted decisions. DR-014 automatic routing remains deferred.

Current development version is **V0-2-0** (owner, 2026-10-18). Remaining Phase 1 provider auth/cold-start checks (A-ST5/A-ST6/A-LM6; P3-P5) and final Phase 1 sign-off are **deferred until V2-0-0**, not waived or passed, and do not block this parity work. GobboNet feature/style implementation and owner visual acceptance remain in current scope.

"All" includes secondary interactions, settings, import/export formats, recovery paths and mobile-width presentation, not just enabling CHARS, MODS and SCHED. Every row below needs an implementation, verification evidence, or a documented provider/security adaptation before parity can be claimed.

### Required adaptations and retained exclusions

- Provider/model selection stays endpoint-aware. Inference, compression and embeddings use verified capabilities of registered providers. Do not translate model selection into load/unload, downloads, tuning, restart or idle stand-down calls. Unsupported sampler fields (including XTC/DRY/token bias) are unavailable with a reason until that provider contract is verified. Different provider capability is a recorded model-dynamics difference.
- Search gets its own fixed-service backend client, protected credential and allowed paths, with threat-model and outbound-policy updates before implementation. Do not weaken the inference endpoint allowlist to accept arbitrary URLs. No arbitrary page crawling is implied by search parity.
- Imported card code remains inert; do not import excluded hook implementations. Preserve unknown card metadata for round-trip where safe, with a clear compatibility report. Treat images/archives as untrusted: bound sizes, entry counts and decompression; reject traversal and executable content. Local image assets must not trigger remote fetches.
- MODS will not reproduce arbitrary JavaScript or arbitrary remote CSS. Macros and safe appearance controls provide supported functionality; record this as an intentional parity exception, not full equivalence of upstream extension execution.
- Backend SQLite replaces browser-authoritative mirror storage. Preserve user outcomes (durability, profiles, restore and conflict protection), rather than duplicating competing sources of truth. Multi-device network access requires a separate HTTPS/auth design; do not add `0.0.0.0` binding or firewall automation. This remains a parity exception under current contracts.
- Installers, PowerShell, inference-engine/process management, executable/model downloads, autostart, recursive uninstall, firewall/antivirus changes remain excluded. No accepted decision is silently changed.

## Implementation sequence and checkpoints

Each milestone is a working vertical slice: migration and store, API/service, real UI, tests, evidence, documentation, then a verified main commit/push. Adapt pinned presentation as its functional screens are implemented. Do not enable controls ahead of their working behavior.

1. **Characters, personas and prompt foundation (CHARS).** Add versioned character/persona/settings/assets storage and conversation/per-message cast references. Implement library/editor CRUD, selection and default cast, greetings/variants, carousel/templates and persona frequency. Refactor `internal/generate` to assemble a validated prompt snapshot, retaining model/provenance data. Add per-character supported sampler and context controls. Check: two characters and two personas survive restart; changing active cast never rewrites historical identity; mock provider receives correct resolved prompts and parameters; imported text cannot execute.
2. **Card interchange and DATA foundation.** Add bounded card parsing and export, native/full snapshot formats and migration/version validation, import preview/merge policy and atomic commits. Preserve cast with single-thread exports and verify round-trip of supported fields and unknown inert metadata. Check malformed PNG/ZIP/JSON, archive traversal/bombs, duplicate IDs, rejected imports leaving DB unchanged, no credentials/scripts activated. Implement safe scoped reset only behind an explicit user action and confirmation.
3. **Complete conversations and organization.** Add folders/tags/pins/order/search; introduce immutable message revisions/variant branches and active-path selection, rather than destructively replacing history. Extend APIs/history builder so only the chosen branch reaches providers. Check forks/variant switching retain their own continuations, edits preserve provenance and canceled/error generations, export/reimport retains relationships; concurrent revisions surface a conflict.
4. **Detached generation and chat tools.** Split durable jobs from request-bound SSE; add job ownership, persisted events or resumable snapshots, bounded replay/retention and explicit Stop. Keep partial text on shutdown and mark interrupted jobs after restart without automatic resubmission. Add attachments, code/math/file actions, reply delivery/limits/watchdog and scroll preferences. Check tab-away/reconnect without duplicate turns, queued cancellation, same-endpoint slot enforcement, unsafe file names/content, safe math/Markdown, and long-stream scroll behavior.
5. **Lore, context management and RAG.** Add authored lore, summary revisions/archive boundaries, compression role, embedding profile/cache and retrieval records. Extend provider interface only after verifying embedding request/response and loaded-model constraints. Add deterministic tag fallback, ranking/budgets and lore/retrieval inspector. Check small-context bounds, failed/oversized summaries preserving source history, manual summary edits, cache invalidation by model/content, retrieval dedupe and no unrequested model loads. A loaded embedding model may require an owner-provided window; report that dependency without claiming semantic RAG verified.
6. **Web search and MODS.** Implement opt-in fixed-service search with DPAPI key and connection test, bounded results and citations. Add macro CRUD/expansion with cycle/size limits and appearance presets that cannot fetch or execute. Check no outbound search while disabled, key redaction, untrusted result text, macro recursion, imported extension data inert and CSP intact. Document intentional arbitrary-JS/CSS parity exceptions.
7. **Scheduler, dashboard and profiles.** Add durable schedules and run ledger, one-off/daily timezone behavior, deduplication, busy/model-unavailable handling, run status and Stop; reuse the job service. Missed schedules are reported, not silently replayed in a burst. Browser closed while server runs must work; app closed cannot execute, and UI must say so. Add home summaries, profile selection, presets and remaining applicable CONFIG/ABOUT interactions. Check restart/timezone/daylight-saving, multiple tabs, repeated ticks, edited/deleted threads, endpoint removal, and no unattended model loading or unlimited auto-continue loops. Add bounded auto-continue chains with cancel and persisted outcome.
8. **Parity and visual acceptance.** Exercise every inventory row against the pin, including secondary dialogs/actions and error paths. Capture full-window and Codex side-panel comparisons; document all model-dynamics adaptations and intentional security exceptions. Finish remaining applicable compatibility settings and regression gaps. Keep the remaining Phase 1 provider auth/cold-start checks and final Phase 1 sign-off deferred until V2-0-0. Claim completed application parity only with an explicit exception list and evidence; final visual acceptance belongs to the owner.

## Architecture and verification rules

- Keep Go backend / SQLite / plain ES modules / vendored browser assets. Add focused packages for prompt assembly, cards/interchange, jobs, memory/retrieval, search and scheduling as their milestones need them; backend/API contracts remain owned by project AGENTS. Extend frontend ownership when modules are added.
- Use additive, tested migrations with a pre-upgrade backup and transactional import. A migration must preserve existing endpoints, credentials, conversations, messages and generation provenance. Profile deletion must never recursively delete arbitrary filesystem paths.
- Snapshot character/persona/parameters/model identity at generation start so changes during a queued job cannot alter its request. Use revisions to prevent concurrent saves overwriting another tab's work. Expose user-facing errors, not success-shaped stubs.
- Verify each vertical slice with meaningful store/service/API tests, fake-provider prompt assertions, relevant security regressions, actual browser interactions, reload/restart checks and live tiny generations only on already-loaded models. Inspect renderer/CSP errors and both required widths.
- Before every code push: `gofmt -l .`, `go vet ./...`, `go test ./...`, `go build ./cmd/labbonet`; retain the CGO-disabled build check and `node --check` for changed browser modules. Main must pass. Update reuse log before copying, architecture/provider/security/acceptance records as changed, closest AGENTS and devlog after each milestone.
- Final inventory must distinguish implemented, verified, owner-pending, provider-blocked and intentionally excluded. A feature with only a button, storage schema or untested code is not complete.
