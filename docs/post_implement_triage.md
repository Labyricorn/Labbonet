## Backend concurrency, resources and lifecycle

- [x] **1.1 · P1 · Supported: isolate retrieval warmth and commit it only for an accepted turn.** `internal/generate/memory.go` (`warmthFor`, `prepareRetrieval`) returns a shared map after releasing its mutex; `internal/memory/retrieve.go` mutates that map. `Runner.Run` assembles the prompt before `Store.StartTurn` checks conflicts. Protect the entire state transition, preferably with a per-conversation reservation and request-local working copy; a map copy alone does not prevent stale updates from competing accepted operations. Do not hold the global warmth mutex across network calls. **Done when:** deterministic overlapping preparations are race-free; conflict, cancellation and failed assembly do not age or add warmth. Coordinate final injection accounting with 2.12f.

  **Fixed 2026-10-18:** retrieval ages/extends a request-local copy (`warmthCopy`); `CommitWarmth` publishes it only after `StartTurn` succeeds, so conflicts, cancellation and failed assembly leave warmth untouched. Residual: overlapping accepted turns on one conversation are last-commit-wins (no per-conversation reservation; see 2.12g); injection accounting still awaits 2.12f.

- [x] **1.2 · P1 · Supported with qualification: close single-use provider transports.** `internal/egress/client.go:61` creates a transport per request with keep-alive enabled and no idle timeout or explicit idle-pool cleanup. EOF/Close can leave an otherwise unused idle pool and its connection goroutines alive. Disable keep-alive for these single-use transports, or introduce explicitly owned reusable transports with shutdown cleanup while preserving privacy-class dial guards and credential isolation. `internal/egress/search.go:58` has the same ownership pattern, but its deferred request-context cancellation may close the connection; the report overstates certainty that both paths leak indefinitely. **Done when:** repeated completed requests to a fake keep-alive server leave bounded connections/resources, including search, errors and body-close paths; redirects and dial guards still pass.

  **Fixed 2026-10-18:** both per-request transports set `DisableKeepAlives`; test asserts no connection stays open after completed requests. Dial guard and redirect refusal unchanged.

- [x] **1.3 · P1 · Supported: make the turn-commit/detachment handoff atomic with cancellation.** `internal/generate/jobs.go` watches `prepare` until `begun`; `runner.go:240` commits the turn before records are persisted and `onStarted` runs at line 263. A disconnect in that interval cancels an already stored turn. Moving the callback earlier narrows but does not eliminate the commit race. Define one synchronized transition that lets pre-commit cancellation abort while preserving post-commit work, and registers Stop/shutdown ownership promptly. **Done when:** barrier-controlled cancellation before, during and after commit gives the documented outcome; committed turns remain detached and cancellable, with no stranded rows/jobs.

  **Fixed 2026-10-18:** `Runner.run` takes a `beforeCommit` hook executed under the watcher's gate immediately before `StartTurn`, so pre-commit cancellation and commit are mutually exclusive; Stop/shutdown registration and `onStarted` now precede the optional record writes. `Jobs.Shutdown` reaches preparing jobs. Barrier-level interleaving of the watcher goroutine is covered by the gate rather than a timing test.

- [x] **1.4 · P1 · Supported: retain in-flight counts when endpoint limits change.** `internal/generate/slots.go` (`semFor`) replaces the channel when the requested limit differs. Old holders and new holders then use independent pools. Use a stable per-endpoint limiter with active count and cancellable waiters; define how a changed stored limit reaches it so stale request snapshots cannot repeatedly reset policy. **Done when:** raising/lowering limits during active and queued calls never grants extra capacity; lowering waits for existing holders to drain rather than cancelling them.

  **Fixed 2026-10-18:** `Slots` keeps one gate per endpoint (active count + FIFO cancellable waiters); the latest Acquire's limit applies, lowering drains rather than cancels.

- [x] **1.5 · P1 · Supported: unify cleanup after scheduler startup.** `cmd/labbonet/main.go` starts the scheduler before `srv.Listen`; both Listen failure and the `srv.Serve` error return bypass normal Stop/Wait while deferred store closure still runs. Install ordered cleanup for every exit after startup: stop launches, cancel work, wait for persistence, close storage. Include preparation jobs in shutdown ownership. **Done when:** occupied-port and injected Serve failures terminate the scheduler/jobs before the database closes, and normal shutdown still saves partial replies.

  **Fixed 2026-10-18:** a once-guarded `cleanup` (scheduler stop, registry cancel, `Jobs.Shutdown`, waits) is deferred right after scheduler start, covering Listen/Serve failures and signals before the store closes. Residual: no `cmd/labbonet` test for occupied-port/Serve injection (package has no test seam); verified by build and the `Jobs.Shutdown` test.

## Backend storage, provider and memory correctness

- [ ] **2.1 · P2 · Supported: make clipping UTF-8 safe.** `internal/generate/memory.go:510` removes continuation bytes from the sliced suffix but leaves the leading byte. - [ ] **2.2 · P2 · Supported: define and implement deletion of referenced endpoints.** `migrations/0001_init.sql` gives conversation/generation endpoint references no delete action; `internal/store/endpoints.go:107` issues a bare DELETE. Referenced endpoints therefore fail deletion. Prefer transactional reference detachment that preserves historical messages/provenance, or explicitly documented conflict refusal; do not silently delete history. Review other endpoint references/settings too. **Done when:** an endpoint with conversation and generation history has a defined non-500 API outcome; credentials/inventory cleanup and history retention are tested, including active work.

- [x] **2.3 · P1 · Supported: enforce disabled endpoints at generation entry points.** `Runner.Run`, `SummarizeNow`, and the chat fallback in `summarizeWithFallback` do not enforce `Enabled`; semantic and dedicated compression selection do.   **Fixed 2026-10-18:** `Run`, `SummarizeNow` and the chat fallback refuse a disabled endpoint (`ErrEndpointDisabled`; 409 at the API, skipped in the scheduler ledger). Requests already running on it drain; they are not cancelled.

- [x] **2.4 · P1 · Supported for clean premature EOF: require stream completion evidence.** `internal/providers/openai/chat.go` checks scanner errors but tracks no terminal marker; `Runner.finalStatus(nil)` then records complete. Track observed terminal evidence while still accepting optional usage after finish. **Done when:** empty/partial clean EOF is a protocol failure with partial text retained; valid finish-only, DONE and usage-tail cases follow the verified provider contract. Use fake streams rather than unapproved live model calls.

  **Fixed 2026-10-18:** `StreamChat` requires a `[DONE]` marker or a finish reason; a clean EOF without either is a protocol error with partial text kept. Usage after the finish chunk is still accepted.

- [ ] **2.6 · P2 · Supported: distinguish shutdown from user Stop in run history.** `internal/generate/scheduler.go` (`execute`) checks `end.Status == "cancelled"` before scheduler-context shutdown; main calls `Registry.CancelAll` during shutdown. - [x] **2.9 · P1 · Supported: separate manual-summary branch scope from archive coverage.** `internal/api/memory.go:201` anchors new/cleared manual summaries at the leaf but reuses an existing effective anchor for nonempty edits. `EffectiveSummary` in `internal/store/memory.go` filters by anchor membership.
